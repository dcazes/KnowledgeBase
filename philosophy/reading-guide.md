# Reading Guide

How the vault is organized and how to read it efficiently.

## Entry points

1. **Root [index](../index.md)** — master index with the build-status table (36 programs, doc counts). Start here.
2. **`architecture/`** — cross-cutting comparisons (search backends, memory, blueprint) that span programs.
3. **Per-program folders** — standard OKF doc sets: `index.md` (entry + Last verified), `overview.md`, `installation.md`, `configuration.md`, `snippets.md`, `ai-integration.md`, `alternatives.md`, plus topic docs.

## Standard doc set (quick map)

| Doc | Answers |
|---|---|
| `index.md` | What is it, contents, role in stack, Last verified |
| `overview.md` | How it works conceptually |
| `installation.md` | How to install/run it (verified versions) |
| `configuration.md` | How to configure it |
| `snippets.md` | Copy-paste cheat sheet |
| `ai-integration.md` | How it connects to agents/AI |
| `alternatives.md` | When to pick what |

## Reading rules

* **Links are relative** (`../memos/index.md`) — valid in Obsidian.
* **Citations** at the end of every doc, numbered, official sources.
* **Last verified** dates tell you how fresh a doc is — docs for unverified/upstream-only tools say so explicitly.
